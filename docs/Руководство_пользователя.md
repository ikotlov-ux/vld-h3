# VLD‑H3. Руководство пользователя

Версия программы 0.8.0. ИПЭЭ РАН, лаборатория биогеоценологии. Техническое задание — [TZ_VLD_script.md](TZ_VLD_script.md), редакция 0.24; ссылки вида «п. 8.3» ведут к его пунктам.

## 1. Назначение

Программа рассчитывает на гексагональной сетке H3 баллы Ценности (V), Нагрузки (L) и Нарушенности (D) экосистем ООПТ г. Москвы, ведёт архив годичных результатов по ООПТ и строит карты. Все баллы имеют три класса: 1 — лучшее состояние (высокая ценность, низкая нагрузка, низкая нарушенность), 3 — худшее; н/д — нет данных. Переключатель «1 — хуже» обращает шкалу в выгрузке и на картах (п. 11.5).

Поставка: файл `vld_h3.py`, папка `resources` (справочники и параметры по умолчанию), примеры файлов параметров в `examples`, это руководство и протокол испытаний.

## 2. Установка

Нужен Python 3.11–3.13 с библиотеками из `requirements.txt`: numpy, pandas, geopandas, shapely, pyproj, pyogrio, h3, openpyxl, Pillow, scipy, rasterio, matplotlib; необязательно — contextily и xyzservices (подложка карт), xlrd (справочники в формате .xls).

Windows. Удобнее всего окружение conda с каналом conda‑forge, где GDAL и PROJ поставляются вместе с библиотеками:

```
conda create -n vld -c conda-forge python=3.12 geopandas pyogrio rasterio scipy openpyxl matplotlib pillow contextily
conda activate vld
pip install h3 xlrd
```

Можно использовать и Python с python.org: `python -m pip install -r requirements.txt`. Если `pip` не может создать временную папку (ошибка доступа), задайте `TEMP` и `TMP` в каталог, доступный на запись.

macOS. Python с python.org (в нём есть Tkinter) или conda; установка — так же. Для экранов Retina масштаб определяется системой.

Linux. Те же команды; для графического интерфейса нужен пакет `python3-tk`.

Проверка установки:

```
python vld_h3.py --version
python vld_h3.py selftest4 --work "проверка установки"
```

Последняя команда за 15–60 с создаёт синтетические данные и проверяет пути с кириллицей и пробелами, кодировки, чтение и запись слоёв и совпадение результатов пакетного режима и интерфейса (разд. 9). Итог — строки `OK`, при отсутствии графической среды проверки интерфейса помечаются «ПРОПУЩЕНО».

Программа сама задаёт пути к данным GDAL и PROJ внутри окружения Python и, если папка настроек matplotlib недоступна на запись, использует временную папку.

## 3. Запуск

```
python vld_h3.py                         # графический интерфейс
python vld_h3.py run --config params.json
```

Без Tkinter работает пакетный режим. Интерфейс и командная строка используют одну схему параметров: файл JSON, сохранённый в интерфейсе, запускается командой `run` с тем же результатом (П12).

## 4. Интерфейс

### 4.1. Окно

Сверху — логотипы, название и версия программы, кнопка «Справочники…». Ниже — восемь вкладок, затем панель с индикатором выполнения, журналом и кнопками «Проверить данные», «Рассчитать», «Остановить», «Построить карты», «Открыть папку результатов», «Загрузить параметры», «Сохранить параметры».

Минимальный размер окна — 1024 × 700. Содержимое вкладок прокручивается колесом мыши или полосой прокрутки, поэтому при экране 1366 × 768 доступны все элементы; на низких экранах журнал и логотипы уменьшаются. Размеры элементов пересчитываются по разрешению экрана, масштаб Windows 125–200 % и Retina разметку не нарушают.

Логотипы читаются из `resources/logos` (`ipee_ran.png`, `lab_biogeocenology.png`, `moscow_coat_of_arms.png`, `dpioos.png`); если файла нет, выводится название организации.

### 4.2. Разделы

Параметры сгруппированы в сворачиваемые разделы. Заголовок раздела содержит стрелку ▸/▾, название и краткую сводку: число выбранных файлов, источник справочника, способ расчёта. У частных показателей есть флажок «вкл.»: выключенный показатель не рассчитывается и исключается из списка «Частные показатели» агрегации V или D (вкладка 5), повторная отметка возвращает его на прежнее место. По умолчанию выключены «Рыбы отдельно» и «Птицы». Изменение списка на вкладке 5 отражается на флажках.

У каждого параметра есть всплывающая подсказка. Типы полей:

| Поле | Действие |
|---|---|
| файл / несколько файлов | «Обзор…» открывает Проводник или Finder с фильтрами типов и мультивыбором; «Просмотр» показывает первые 20 строк (п. 4.3); пути разделяются «;» |
| слой GPKG | выпадающий список слоёв выбранного файла |
| поле данных (широта, вид, ФГ и др.) | выпадающий список полей выбранного файла; пустое значение — автоподбор, подобранное имя показано в подсказке |
| выбор ООПТ | список с флажками; пустой выбор — все ООПТ слоя границ |
| набор параметров | «Применить набор» заменяет значения встроенным набором (разд. 7) |

### 4.3. Предпросмотр файла

Окно показывает: для CSV — определённые кодировку (UTF‑8, UTF‑8‑SIG, CP1251), разделитель (`,`, `;`, табуляция) и десятичный знак; для XLSX — список листов и строку заголовка (0 — автоподбор по полям координат или `h3_id`); для GPKG — список слоёв; для всех — найденные поля широты, долготы, вида, ФГ, таксономической группы и первые 20 строк. Кнопка «Применить к параметру» записывает выбранный лист, слой и строку заголовка в путь файла (п. 5.1).

### 4.4. Справочники

Кнопка «Справочники…» открывает список табличных справочников: ООПТ и синонимы; зональность по типу экосистемы (прил. Г), баллы кодов вне таблицы и баллы классов типологии 2025 г. (прил. Е); соответствие типа экосистемы энтомологическому биотопу (прил. Д); матрица контраста границ ECON; знаки метрик фрагментации; перекодировка категорий редкости; справочники «вид → ФГ» млекопитающих, амфибий и рептилий, рыб; охраняемые растения и грибы; чужеродные инвазивные растения; чужеродные инвазивные виды животных; матрицы решений. Для выбранного справочника выводятся источник (встроенный, `resources`, параметр или внешний файл), таблица и кнопки:

- «Выгрузить…» — в CSV (UTF‑8 с BOM, разделитель «;») или XLSX;
- «Заменить из файла…» — справочник, хранящийся в параметрах (зональность, ECON, знаки, перекодировка, матрицы), записывается в текущий набор параметров; справочник видов или ФГ подключается как внешний файл соответствующего раздела; справочник ООПТ записывается в `resources/defaults.json` (предыдущая версия сохраняется как `.bak`);
- «Вернуть встроенный».

Поклеточного редактирования нет: таблицу удобно выгрузить, исправить в Excel и загрузить обратно.

### 4.6. Порядок работы

1. На вкладке 1 выбрать набор параметров и нажать «Применить набор», указать слой границ, при необходимости — ООПТ и папку результатов.
2. В разделах вкладок 2–4 указать файлы первичных данных; через «Просмотр» проверить лист, кодировку и подобранные поля.
3. «Проверить данные»: отсутствующие файлы и поля, координаты, рекомендация способа А или Б по каждой ООПТ.
4. «Рассчитать». Расчёт идёт в фоновом потоке, «Остановить» прерывает его без порчи ранее записанных файлов.
5. «Построить карты» — по последнему расчёту или по ранее выгруженному слою.
6. «Сохранить параметры» — файл JSON для повторного запуска в интерфейсе или командой `run`.

## 5. Входные данные

### 5.1. Ссылки на файлы

| Запись | Значение |
|---|---|
| `файл.gpkg` | первый подходящий слой |
| `файл.gpkg::слой` или `файл.gpkg\|layername=слой` | слой GeoPackage (вторая форма — как в QGIS) |
| `файл.xlsx::лист` | лист книги |
| `файл.xlsx::лист::3` | лист и номер строки заголовка (строки выше пропускаются) |
| `файл.xlsx::::3` | первый подходящий лист, заголовок в 3‑й строке |

Пути могут содержать кириллицу и пробелы. В Windows конечный пробел в имени папки удаляется системой, такие папки следует переименовать.

### 5.2. Таблицы и слои

- CSV — кодировка и разделитель определяются автоматически; десятичная запятая допускается при разделителе «;».
- XLSX и XLS (для .xls нужен xlrd).
- SHP — кодировка из файла `.cpg` (UTF‑8 или CP1251); при выгрузке пишется UTF‑8 с `.cpg`.
- GPKG — слои с кириллическими именами.
- Таблицы с координатами — поля широты и долготы подбираются по именам (lat, latitude, широта, Y, POINT_Y; lon, long, longitude, долгота, X, POINT_X); система координат — EPSG:4326.

### 5.3. Контроль

Точки вне диапазона широты 55,1–56,1 и долготы 36,8–38,1 исключаются, перестановка широты и долготы исправляется; точки дальше 10 км от ООПТ исключаются; геометрии исправляются (`make_valid`); виды, не найденные в справочниках, выводятся в журнал и отчёт (п. 5.7, 6.5).

## 6. Алгоритмы

### 6.1. Сетка

В сетку входят ячейки H3 (по умолчанию разрешение 11, около 2 150 м²), центры которых лежат внутри ООПТ. При наложении полигонов ячейка относится к ООПТ с большей площадью пересечения. Полигон, не менее чем на 90 % лежащий в другой ООПТ, вырезается из неё и считается разделом (Бирюлёвский дендропарк в Царицыне); учёты ООПТ распространяются на раздел (п. 7.1–7.3а).

Площадные слои (экосистемы D2, патчи фрагментации) переносятся на гексагоны через растр 5–10 м: гексагон получает выдел или класс с наибольшей долей площади, непрерывные величины — среднее по ячейкам (п. 7.5).

Слой экосистем D2 принимается в двух типологиях. Типология 2026 г. — числовой код типа (`110–504`, `1110–4504`). Типология 2025 г. — карты ЦЭПЛ с полем `Class` (или `ClassName`) и классами `Б`, `БКл`, `Лп`, `Тр`, `Антр` и др.; она распознаётся автоматически (параметр «Типология слоя»), файл типологии D3 к ней не применяется, а зональность, биотоп насекомых и класс фрагментации берутся по классу (ТЗ, прил. Е). Контуры одного класса с общей границей объединяются в один выдел (параметр «Объединять смежные контуры одного класса»). В выходном слое класс записан кодом `900 + RasterValue` (`eco_code` 901–939). В одном расчёте можно подать файлы обеих типологий.

### 6.2. Ценность

| Показатель | Значение | Балл 1 / 2 / 3 |
|---|---|---|
| насекомые `v_ins` (п. 8.2) | среднее `RATING` повторных площадок пары «ООПТ × биотоп», min–max нормировка; биотоп гексагона — по типу экосистемы (прил. Д) или классу ЦЭПЛ (прил. Е); травяная растительность `Тр` — среднее `dry` и `wet` | > 2/3 / (1/3; 2/3] / ≤ 1/3 |
| млекопитающие `v_mam` (п. 8.3) | число ФГ в окне k = 10 колец (≈ 71 га) | ≥ 5 / 3–4 / 1–2 ФГ |
| низшие позвоночные `v_anam` (п. 8.4) | число ФГ амфибий, рептилий и рыб (хищники, всеядные, планктофаги) в окне k = 10 колец | 3 / 2 / 1 ФГ |
| рыбы отдельно `v_fish` (п. 8.4а; по умолчанию выкл.) | число ФГ в водоёме; только водные гексагоны (доля воды ≥ 2 %); водоёмы — OSM или слой пользователя | 3 / 2 / 1 ФГ |
| птицы `v_bird` (по умолчанию выкл.), гидробионты `v_aqua` (п. 8.5–8.6) | готовое число ФГ или балл по точкам и водоёмам | терцили или балл источника |
| редкие растения `v_rare` (п. 8.7) | наивысший охранный статус сосудистых растений в гексагоне; категория из находки, при отсутствии — из справочника | ККМ 0–2 / 3–6 / нет находок |
| ёмкость выдела `v_cap` (п. 8.8) | площадь выдела D2 | > 50 / 5–50 / ≤ 5 га |
| зональность `v_zon` (п. 8.9) | балл типа экосистемы по типологии 2026 г.; коды вне таблицы — по списку; классы ЦЭПЛ — параметр «Баллы классов типологии 2025 г.» (п. 8.9.6) | по таблице |
| QBS почв `v_qbs` (п. 8.10) | ближайшая проба той же ООПТ, последний год не позднее года расчёта | > 350 / (250; 350] / ≤ 250 |

Расчёт ведётся способом А; способ Б (IDW) временно отключён, значение `B` в прежних файлах параметров читается как А (п. 8.3.4). Если включить «Рыбы отдельно» при включённых рыбах в низших позвоночных, программа предупредит о двойном учёте. При сверке рыб с водоёмами допуск по названию — 150 м, синонимы названий прудов задаются параметром «Синонимы названий водоёмов». Находки чужеродных инвазивных видов в ФГ не учитываются. В обследованной ООПТ гексагон без находок получает н/д (редкие растения — балл 3).

Внешние справочники «вид → ФГ» (D11) подключаются в разделах млекопитающих, низших позвоночных и рыб. Параметр «Внешний справочник ФГ» задаёт, как файл сочетается со встроенным справочником: «дополняет встроенный» (по умолчанию; новые виды добавляются, при расхождении ФГ вида действует файл), «объединяется со встроенным» (у вида остаются все ФГ обоих справочников, как в версии 0.5), «заменяет встроенный». Расхождения ФГ записываются в журнал и отчёт `fg_ref_<группа>`. Поля вида и ФГ подбираются автоматически, в том числе в таблицах ФГ 2025 г. (CSV, XLSX, XLS); справочник в текущем виде выгружается через «Справочники…» как шаблон D11 (поля «вид (латынь)», «вид (русск.)», «ФГ», «ФГ (название)»).

V_mean — взвешенное среднее имеющихся частных баллов (н/д исключаются; по умолчанию веса 1, минимум один показатель).

### 6.3. Нагрузка

Фотографии с геотегами (дубликаты по паре «снимок, автор» удаляются) и рекреационные объекты (здания не учитываются) переводятся в категории `photo_cat` и `infra_cat` (1–5); `l_raw = photo_cat + infra_cat − 2`; L: 0 → 1, 1–3 → 2, ≥ 4 → 3. Можно подать готовый слой `load_cat` по `h3_id` (разд. 9).

### 6.4. Нарушенность

| Показатель | Значение | Балл 1 / 2 / 3 |
|---|---|---|
| инвазивные растения `d_inv` (п. 10.1) | число растений видов справочника проекта (69 таксонов) в гексагоне | 0 / 1–2 / ≥ 3 |
| фрагментация `d_frag` (п. 10.2) | растр 10 м по шести классам (лес, луг, кустарник, болота, вода, антропоген), рассечение дорогами с твёрдым покрытием и зданиями, патчи ≥ 0,1 га; ранги ECON и ENN (рост — хуже), SHAPE и CONTIG (снижение — хуже); среднее по ячейкам гексагона | терцили Excel индекса |
| чужеродные виды животных `d_alien` (п. 10.3) | число видов справочника в своём гексагоне; водные виды — окрестность 100 м в пределах контура водоёма | 0 / 1 / ≥ 2 вида |

D_mean — среднее имеющихся баллов; если какого‑то показателя нет, сумма делится на число оставшихся (п. 10.4).

### 6.5. Квантование

V_mean и D_mean переводятся в три класса (п. 11): по умолчанию — терцили Excel по всем гексагонам расчёта (`PERCENTRANK.INC`, 3 знака, границы 0,33 и 0,66), как в 2025 г.; доступны фиксированные пороги (пороги 2025 г. записаны в наборе «2026 — базовый»), равные интервалы, округление (Excel ROUND), прямые категории, сбалансированные терцили. Домен — все гексагоны расчёта, каждая ООПТ, эталонная выборка или объединение с архивом. L — прямые категории. Отчёт о квантовании выводит пороги и доли классов.

|---|---|
| 2025 — воспроизведение V4 | частные баллы V4 без изменений, QBS 0 как число; V и D — совместные терцили Excel |
| 2025 — исправленный | балл инвазивных растений по основному правилу, QBS 0 → н/д |
| 2026 — базовый | все частные показатели, кроме выключенных рыб отдельно и птиц; чужеродные виды животных; параметры по решениям п. 17.1 ТЗ |

Набор «2026 — базовый» содержит значения по умолчанию для вопросов, ещё открытых в п. 17.2 ТЗ (птицы, гидробионты, насекомые, веса водных границ ECON); после решений меняются только эти значения. Палитры L и D по умолчанию: 1 — зелёный, 3 — красный.

Результаты 2025 г. из V4 — зафиксированное состояние: они хранятся в архиве и входят в сборки до перерасчёта ООПТ на 2026 г.

## 8. Результаты и архив

- Слой GPKG (`vld_hex`) или SHP: `h3_id`, `oopt`, `calc_year`, `V`, `L`, `D`; по выбору — частные баллы, средние, счётчики (прил. В).
- Сводная таблица XLSX (по выбору): доли классов по ООПТ и годам, сопряжённость, пороги, состав V.
- Файл параметров JSON: параметры, версии библиотек, SHA‑256 входных файлов и таблицы атрибутов, журнал.
- Таблицы сверки рыб с водоёмами и находок чужеродных видов (CSV).
- Архив `vld_archive.gpkg`: срезы `(oopt_id, calc_year)`; сборка по последнему году каждой ООПТ, выбранному году или вручную; межгодовые матрицы переходов (п. 12.5).
- Карты PNG, PDF, TIFF и слой карт GPKG со стилями QGIS (разд. 13).

## 9. Командная строка

```
python vld_h3.py run --config params.json [--set раздел.поле=значение] [--replace]
python vld_h3.py check --config params.json
python vld_h3.py config --preset "2026 — базовый" --out params.json
python vld_h3.py import-v4 V4.xlsx --archive vld_archive.gpkg
python vld_h3.py archive-list --archive vld_archive.gpkg
python vld_h3.py export --archive vld_archive.gpkg --out out --rule last --xlsx
python vld_h3.py transitions --archive vld_archive.gpkg --oopt IZM --y1 2025 --y2 2026 --out out
python vld_h3.py maps --config params.json --layer vld_2026.gpkg
python vld_h3.py zones-template --out matricy.csv
python vld_h3.py defaults --out resources/defaults.json
```

Автотесты: `selftest` (П1–П3, П5, П10, П11; нужен V4), `selftest2` (П4, П7, П9; данные 2026 г.), `selftest3` (П8, карты), `selftest4` (П6, П12; синтетические данные, без сети; ключ `--no-gui` отключает проверки интерфейса). Результаты — в [протоколе испытаний](Протокол_испытаний.md).

## 10. Типичные сообщения

| Сообщение | Причина и действие |
|---|---|
| «нет листа …; листы: …» | неверное имя листа в `файл::лист`; выбрать лист в «Просмотр» |
| «не найдено поле «широта (…)»» | в таблице нет поля координат с узнаваемым именем; указать поле вручную |
| «ООПТ … нет в справочнике синонимов; присвоен идентификатор …» | новое название; добавить синоним через «Справочники…» → ООПТ |
| «в данных 2 ФГ; … балл 1 недостижим» | в низших позвоночных нет рыб (данные без рыб или выключен параметр «Включать рыб») |
| «… показатель выключен (флажок «вкл.»), не рассчитывается» | данные поданы, но флажок раздела снят; включить при необходимости |
| «способ «B» временно отключён; принят способ А» | файл параметров прежней версии; способ Б временно отключён (п. 8.3.4) |
| «рыбы: загрузка водоёмов OSM» долго не завершается | нет доступа к Overpass API; указать слой водоёмов пользователя (раздел «Рыбы отдельно», «Водоёмы» → «слой пользователя») или ранее сохранённый кэш |
