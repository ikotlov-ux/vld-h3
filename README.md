# VLD-H3

Программа расчёта баллов Ценности, Нагрузки и Нарушенности (V, L, D) экосистем ООПТ г. Москвы на гексагональной сетке H3, ведения многолетнего архива результатов по ООПТ и построения карт. ИПЭЭ РАН, лаборатория биогеоценологии.

Техническое задание: [docs/TZ_VLD_script.md](docs/TZ_VLD_script.md) (редакция 0.15).

## Состояние

| Этап | Содержание | Состояние |
|---|---|---|
| 1 | ядро: схема параметров, CLI, сетка H3, импорт V4, архив годичных результатов, разнолетняя сборка, квантование, выгрузка, каркас GUI (вкладки 1, 5, 6, 8) | выполнен (версия 0.1.0) |
| 2 | частные показатели 2026 г. по первичным данным (V, L, D), перенос площадных слоёв через сетку 5–10 м, фрагментация по патчам, разделы GUI на вкладках 2–4 | выполнен (версия 0.2.0) |
| 3 | карты: один параметр, частные показатели, пары 3 × 3, куб CIELAB, матрицы решений; карты в гексагонах и в контурах экосистем D2; слой карт GPKG со стилями QGIS; вкладка 7 GUI | выполнен (версия 0.3.1) |
| 3а | рыбы — отдельный показатель в пределах водоёмов OSM; выбор способа А или Б пользователем с рекомендацией по числу единиц учёта | выполнен (версия 0.4.0) |
| 3б | чужеродные инвазивные виды животных `d_alien`; справочники видов: охраняемые растения и грибы, охраняемые животные, чужеродные инвазивные растения и животные; категория `v_rare` по справочнику, отбор находок `d_inv` по справочнику | выполнен (версия 0.5.0) |
| 4 | доводка GUI, руководство, проверка на Windows и macOS | — |

Частные баллы подаются двумя способами: импортом файла V4 или таблиц готовых баллов по `h3_id` (поля `v_*`, `d_*`, `load_cat`, `inv_n`) либо расчётом по первичным данным (этап 2). Если для показателя заданы первичные данные, он рассчитывается; остальные показатели берутся из импорта или остаются н/д.

Первичные данные этапа 2:

| Показатель | Вход |
|---|---|
| зональность `v_zon`, ёмкость `v_cap` | слой экосистем D2 (выделы с кодом типа), типология D3 (лист с полями «Тип» и «Зональность»); коды вне таблицы — по списку «Баллы кодов вне таблицы» (по умолчанию 143, 223, 224, 233, 501, 504 → 3) |
| насекомые `v_ins` | таблица рейтингов площадок (OOZT, BIOTOP, PLOT, RATING) и координаты площадок |
| млекопитающие `v_mam`, амфибии и рептилии `v_anam` | точки находок (XLSX/CSV, поля широты и долготы), справочники «вид → ФГ»; рыбы исключаются по полю таксономической группы или по справочнику |
| рыбы `v_fish` | те же таблицы низших позвоночных; ФГ: 1 — хищники, 2 — всеядные, 3 — планктофаги (уклейка — планктофаг); водоёмы — OpenStreetMap (Overpass API, кэш в папке результатов) или собственный слой; показатель — только в водных гексагонах |
| птицы `v_bird`, гидробионты `v_aqua` | единицы учёта и водоёмы с готовым числом ФГ или баллом |
| редкие растения `v_rare` | точки с названием вида и (или) категорией; категория — из находок, при отсутствии — из справочника охраняемых видов; шкала ККМ (гор. или пр. по списку ООПТ), ККРФ или МСОП; виды только Приложения 4 к 79-ПП — код 6; учитываются сосудистые растения |
| QBS `v_qbs` | значения по точкам и годам; пороги 250 и 350; перенос — ближайшая точка в той же ООПТ, последний год не позднее года расчёта |
| нагрузка `load` | фотографии с координатами, рекреационные объекты |
| инвазивные `d_inv` | точки растений (число растений в гексагоне); по умолчанию учитываются виды справочника инвазивных растений (369-ПП, ТОП-100, Чёрная книга флоры Средней России), вариант — только перечень 369-ПП |
| чужеродные животные `d_alien` | находки из блоков млекопитающих, амфибий и рептилий, рыб и дополнительные таблицы; число видов справочника в гексагоне (0 → 1, 1 → 2, ≥ 2 → 3); водные виды — окрестность 100 м в пределах контура водоёма; в ФГ эти виды не учитываются |
| фрагментация `d_frag` | слой D2, дорожно-тропиночная сеть и здания; классы лес, луг, кустарник, болота, вода, антропоген; ECON, ENN, SHAPE, CONTIG, PARA |

Слой экосистем D2 можно задать несколькими файлами; если ООПТ присутствует в нескольких файлах, используются выделы последнего в списке (например, общий слой 2025 г. и обновлённый слой одной ООПТ 2026 г.).

Способ переноса ФГ (А — прямой подсчёт, Б — IDW по единицам учёта) выбирает пользователь для каждого блока; по умолчанию — А. Кнопка «Проверить данные» и команда `check` выводят по каждой ООПТ число единиц учёта и рекомендацию (Б — при 30 единицах и более и медиане расстояния до соседней единицы не более половины радиуса IDW).

Рыбы сверяются с водоёмами: «в водоёме», «в допуске» (по умолчанию 30 м; из нескольких водоёмов предпочитается одноимённый с полем «водный объект»), «по названию» (параметр `name_tolerance`, по умолчанию выключен), «вне водоёма» (исключается). Таблица сверки — `<имя>_ryby_sverka.csv`. Данные OpenStreetMap распространяются по лицензии ODbL 1.0 (© участники OpenStreetMap).

Результаты 2025 г. из V4 (11 ООПТ) — зафиксированное состояние: в архиве они не пересчитываются и попадают в сборку «последний доступный год», пока для ООПТ нет среза 2026 г.; показатель `v_fish` в них — н/д. Кусково, Покровское-Стрешнево и Царицыно впервые рассчитываются в 2026 г.

Слой GeoPackage указывается как `файл.gpkg::слой`; без указания слоя выбирается первый подходящий по геометрии и имени.

## Установка

Python 3.11–3.13:

```
pip install -r requirements.txt
```

Для карт дополнительно нужны `matplotlib`, для подложки — `contextily` и `xyzservices` (без них карты строятся без подложки).

Tkinter входит в стандартные сборки Python для Windows и macOS (python.org). Без Tkinter работает пакетный режим.

## Запуск

```
python vld_h3.py                                   # графический интерфейс
python vld_h3.py run --config params.json          # расчёт по файлу параметров
python vld_h3.py run --preset "2025 — воспроизведение V4" --set inputs.v4_path=V4.xlsx --set check.reference_path=V4.xlsx
python vld_h3.py import-v4 V4.xlsx --archive vld_archive.gpkg      # результаты 2025 г. в архив
python vld_h3.py archive-list --archive vld_archive.gpkg
python vld_h3.py export --archive vld_archive.gpkg --out out --rule last --xlsx
python vld_h3.py export --archive vld_archive.gpkg --out out --rule manual --manual "BIT=2025, KUS=2026"
python vld_h3.py transitions --archive vld_archive.gpkg --oopt IZM --y1 2025 --y2 2026 --out out
python vld_h3.py check --config params.json                   # проверка данных и рекомендация способа А или Б
python vld_h3.py config --preset "2026 — базовый" --out params.json
python vld_h3.py selftest --v4 V4.xlsx --work test --bounds2026 "Границы ООЗТ.gpkg"
python vld_h3.py selftest2 --config params2026.json --work test2 --v4 V4.xlsx
python vld_h3.py maps --config params.json --layer vld_2026.gpkg      # карты по готовому слою без пересчёта
python vld_h3.py maps --config params.json --archive vld_archive.gpkg # карты по архиву (правила сборки)
python vld_h3.py zones-template --out matricy.csv                     # шаблон матриц решений
python vld_h3.py selftest3 --layer vld_2026.gpkg --work test3 --bounds "Границы ООЗТ.gpkg"
python vld_h3.py defaults --out resources/defaults.json      # выгрузить встроенные справочники
```

Любой параметр файла JSON переопределяется ключом `--set раздел.поле=значение`. Один и тот же файл параметров в GUI и CLI даёт одинаковые таблицы атрибутов (П12).

## Карты

Карты строятся в ориентации «1 — лучше» (слой в ориентации «1 — хуже» читается с ключом `--worst1`):

| Вид | Классов | Оформление |
|---|---|---|
| V, L, D и частные показатели (`v_zon`, `v_cap`, `v_mam`, `d_inv`, `d_frag` и др.) | 3 (у `photo_cat`, `infra_cat` — 5) | линейная легенда; подписи частных показателей следуют порогам конфигурации |
| V × L, V × D, L × D | 9 | матрица 3 × 3 с числом и долей гексагонов; палитра «2025 «ЦВЕТА»», срез куба или пользовательская |
| V × L × D | 27 | куб CIELAB, три среза по V; проверка различимости (минимальное ΔE76, по умолчанию 9,2) |
| V × D, V × L, L × D, V × L × D — матрицы решений | по шаблону | встроенные шаблоны V × D и V × L; остальные — по файлу CSV (`zones-template`) |

Для каждой ООПТ и для обзора всех выбранных ООПТ создаются PNG/PDF/TIFF (имена с кириллицей допускаются), рамка, стрелка севера, линейный масштаб с поправкой на широту (ошибка ≤ 0,3 %), год расчёта. Слой `<имя>_karty.gpkg` содержит по слою `map_<вид>` на каждую карту (поля `cls`, `label`, `color`, исходные баллы, для матриц решений — `code`) и таблицу `layer_styles`: в QGIS слой открывается сразу с легендой карты.

Карты в контурах экосистем (параметр «Единицы карт»: гексагоны, контуры экосистем D2 или оба варианта). Баллы гексагонов переносятся в выделы слоя D2 раздела «Экосистемы», обрезанные областью ООПТ; вес гексагона равен площади его пересечения с выделом. Способ переноса: преобладающий по площади класс (по умолчанию; при равенстве — меньший номер) или средневзвешенный по площади балл, округлённый до целого. Если баллом покрыто меньше 0,5 площади выдела (параметр), выдел получает н/д. Пары и V × L × D составляются из перенесённых V, L, D. В легенде указывается площадь выделов (га), к имени файла добавляется «_контуры», в слое карт появляются слои `eco_<вид>` с полями `eco_code`, `area_ha`, `n_hex`, `cover` и долями площади присвоенного класса (`V_share` и др.).

Подложка: OpenStreetMap (осветлённая, по умолчанию), Esri World Gray Canvas, OpenStreetMap HOT или без подложки. Тайлы кэшируются в папке результатов. CartoDB с 2025 г. требует ключ API; при недоступности подложки (ошибка сети, заглушка вместо тайлов) карта строится без неё с предупреждением в журнале.

## Справочники

`resources/defaults.json` содержит справочник ООПТ и синонимов, наборы параметров, пороги 2025 г., таблицу H3, справочники «вид → ФГ», встроенную таблицу зональности, соответствие «тип экосистемы → BIOTOP», матрицу контраста ECON и знаки метрик фрагментации. При отсутствии файла используются встроенные значения; синонимы ООПТ из файла дополняют встроенные.

Справочники видов (UTF-8, разделитель «;»; порядок выбора: файл, заданный в параметрах, → `resources/ref_*.csv` → встроенная таблица):

| Файл | Содержание | Используется |
|---|---|---|
| `ref_protected_plants.csv` | 451 таксон: сосудистые растения, мхи, лишайники, грибы, водоросли Красной книги города Москвы (2022) и Приложения 4 к постановлению № 79-ПП; категории ККМ гор. и пр., ККРФ (приказ Минприроды России № 320), МСОП | `v_rare` |
| `ref_protected_animals.csv` | 483 таксона животных ККМ и Приложения 4; категории ККРФ (приказ № 162 в ред. № 313), МСОП | справочно |
| `ref_invasive_plants.csv` | 69 таксонов: постановление Правительства Москвы № 369-ПП (группы I–IV), ТОП-100, Чёрная книга флоры Средней России | `d_inv` |
| `ref_alien_animals.csv` | 15 чужеродных инвазивных видов животных со средой обитания | `d_alien`, исключение из ФГ |

Находки сопоставляются по латинскому названию, синонимам и русскому названию; записи ранга рода и выше — по роду или семейству. Полные справочники с источниками — в материалах проекта (XLSX, листы «Справочник», «Поля», «Источники»).

## Архив годичных результатов

`vld_archive.gpkg`: слой `vld_yearly` (ключ `oopt_id, calc_year, h3_id`), таблицы `runs_meta` (параметры, пороги, SHA-256 входных файлов по каждому срезу) и `oopt_dict` (справочник синонимов ООПТ), по выбору `oopt_bounds`. Запись выполняется через временную копию с последующей заменой файла.

## Данные

Входные данные (в том числе координаты видов Красной книги) в репозиторий не включаются (п. 4.7 ТЗ). Логотипы организаций размещаются пользователем в `resources/logos` (п. 5.2 ТЗ).
